        tracker.gg access
        
          
        
            tracker.gg puts a Cloudflare challenge in front of match data. It has to be
            cleared in the browser on the server, because the pass is tied to the
            server's address - solving it here in your own browser would not count. This
            opens that browser in a window below so you can click the challenge from
            anywhere, without needing access to the server itself. Press Done once the page
            has loaded past the challenge - the window has no title bar to close.

        Your OBS key
        
          
        
            Every OBS browser source and both game webhooks carry this key - it is what
            tells the server which production they belong to, since OBS cannot sign in.
            Treat it as a password that happens to live in a URL: anyone holding it can
            watch your graphics and feed your agent select.

            A new key stops every existing URL working at once. Use it if a key has been
            on stream - then re-copy the URLs into OBS from the three graphics tabs.

            Button actions - what to send
            
        
              One line in Send generic command, on the button's press action.
              Case and separator do not matter, and {"op":"winner.stage","value":2}
              is accepted where an action needs a number.
            
        
            
        
          
        

          
        
            Button feedback - the variables
            
        
              Companion creates none of these on its own. For each one you want, add the feedback
              "Update variable with value from WebSocket message" to a button, put
              the name in both the JSON Path and the Variable box, and read it back
              as $(<connection>:<name>). The separator is a dot - the module's
              own help page says slashes, and that is wrong. A path that matches nothing fails
              silently and leaves the old value on screen.
            
        
            
        
              Put every one of these feedbacks on a single spare button and read the variables from
              the buttons that show them: a variable only exists while some button subscribes to it.
              To colour a button, use Companion's own Variable: Check value against
              the _n form - it is 1 or 0, which compares cleanly where a true/false may not.
